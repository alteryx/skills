# Security Policy

Do not report vulnerabilities or safety issues through public GitHub issues,
pull requests, discussions, comments, or commit messages.

Public reports can expose sensitive details before remediation. Do not post
secrets, credentials, tokens, API keys, private certificates, customer data,
personal data, proprietary workflows, confidential information, exploit details,
or vulnerability reproduction steps in public repository surfaces.

## Reporting a Vulnerability

- Customers should report security issues through http://trust.alteryx.com/.
- Non-customers should report security issues to security@alteryx.com.

Include only the information needed for Alteryx to triage the report. If a
report may contain sensitive material, use the private reporting channel first
and wait for guidance before sharing more detail.

## Triage and Response

The Ask Alteryx team owns repository-level triage and coordinates with Alteryx
Security for vulnerability assessment, remediation, disclosure timing, and any
required escalation.

Maintainers should avoid public confirmation of vulnerability details until
Alteryx Security has approved the response path.
